# 01. Архитектура системы

## 1.1. Принципы

1. **Modular monolith.** Один деплой-артефакт для API. Модули изолированы по
   границам домена и общаются через сервисные интерфейсы, а не напрямую через
   чужие репозитории. Микросервисы не вводим: на MVP они дают стоимость
   инфраструктуры без выигрыша.
2. **Tenant-first.** `companyId` — обязательный элемент любого запроса к данным
   арендатора. Изоляция обеспечивается на трёх уровнях (см. 07-security-model).
3. **Grounded AI.** Модель не имеет права называть товар или цену, которых нет
   в БД компании. Все фактические данные приходят только через tools.
4. **Channel-agnostic ядро.** Telegram — первый канал, но диалог, сообщение и
   лид не знают о Telegram. Канал — адаптер на входе и на выходе.
5. **Синхронный MVP, асинхронный дизайн.** Webhook отвечает Telegram мгновенно
   (200 OK), обработка идёт в фоне процесса. Точка расширения — вынести в
   очередь (BullMQ/Redis) без изменения доменного слоя.

## 1.3. Слои внутри API

| Слой | Ответственность | Правила |
|---|---|---|
| `routes` | HTTP-маршрут, middleware-цепочка | Не содержит бизнес-логики |
| `controller` | Разбор запроса, вызов сервиса, формирование ответа | Валидирует вход через Zod |
| `service` | Бизнес-логика, транзакции, инварианты | Не знает про `req`/`res` |
| `repository` | Доступ к данным через Prisma | Всегда принимает `companyId` |
| `core` | Ошибки, логгер, конфиг, безопасность | Не зависит от модулей |

Импорт разрешён строго вниз: `routes → controller → service → repository → core`.
Кросс-модульные вызовы допустимы только на уровне `service → service`.

## 1.4. Ключевые потоки

### Поток A — входящее сообщение клиента

1. Telegram отправляет update на `POST /api/v1/webhooks/telegram/:channelId`.
2. Middleware проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.
3. Контроллер немедленно отвечает `200 OK` (Telegram не ретраит).
4. `TelegramDispatcher` в фоне:
   - находит `Channel` → `Company` (это единственная точка, где определяется арендатор);
   - upsert `Customer` по `(companyId, telegramUserId)`;
   - получает/создаёт активный `Conversation`;
   - сохраняет входящее `Message`;
   - вызывает `AiAgentService.reply()`;
   - отправляет ответ и (при необходимости) карточки товаров/кнопку контакта.

### Поток B — цикл AI

1. `PromptBuilder` собирает system prompt: профиль компании + база знаний + FAQ +
   инструкции + правила анти-галлюцинаций + состояние лида.
2. История диалога загружается окном (последние N сообщений + сжатая сводка).
3. Модель вызывается с набором tools; исполнение tools — в `ToolExecutor`,
   который принудительно подставляет `companyId` из контекста запроса.
4. Цикл tool-use ограничен `AI_MAX_TOOL_ITERATIONS` (по умолчанию 5).
5. Побочные эффекты (создание лида, передача менеджеру, запрос контакта)
   возвращаются наверх как `AgentEffect[]` и исполняются каналом.

### Поток C — админ-панель

Nuxt SPA → `Bearer <access token>` → REST API. Компания определяется из токена,
а не из тела запроса. Клиент никогда не передаёт `companyId`.

## 1.5. Технологические решения

| Решение | Выбор | Почему |
|---|---|---|
| Стиль архитектуры | Modular monolith | Скорость MVP, одна транзакционная граница |
| ORM | Prisma | Типобезопасность, миграции, скорость разработки |
| Мультиарендность | Shared DB + `companyId` + guard-extension | Дёшево, проверяемо, достаточно для MVP |
| Валидация | Zod на каждой границе | Единый источник правды для типов и рантайма |
| Аутентификация | JWT access (15 мин) + refresh (30 дней, хэш в БД) | Stateless API, отзывные сессии |
| Пароли | scrypt (Node crypto) | Memory-hard, без нативных сборок |
| Секреты каналов | AES-256-GCM в БД | Токен бота — доступ к переписке клиента |
| AI | OpenAI + function calling | Инструменты дают фактическую заземлённость |
| Фон | in-process очередь | Нет Redis в MVP; интерфейс готов к замене |

## 1.6. Что осознанно НЕ входит в MVP

- Микросервисы, Kafka, отдельный AI-сервис.
- Векторный поиск/RAG (каталог мебели помещается в SQL-фильтры + LIKE).
- Голосовая транскрипция (voice принимается, но отвечаем текстом-заглушкой).
- Биллинг и тарифы.
- Каналы Instagram/WhatsApp (интерфейс `ChannelAdapter` подготовлен).

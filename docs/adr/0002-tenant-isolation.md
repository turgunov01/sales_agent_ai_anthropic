# ADR-0002. Изоляция арендаторов: общая БД + companyId + guard

**Статус:** принято · **Дата:** 2026-08-22

## Контекст

Данные разных магазинов не должны пересекаться никогда. Варианты: отдельная БД
на арендатора, схема на арендатора, общая схема с дискриминатором.

## Решение

Общая схема с обязательным `companyId` и тремя рубежами защиты:
источник `companyId` только из JWT/канала, репозитории с обязательным скоупом,
Prisma-расширение, отклоняющее запрос к модели арендатора без `companyId`.

## Альтернативы

- **База на арендатора** — надёжнее, но миграции и подключения умножаются на
  число клиентов; для десятков арендаторов это неоправданная операционная цена.
- **PostgreSQL RLS** — сильный вариант, но требует прокидывать
  `SET LOCAL app.company_id` в каждую транзакцию Prisma; на MVP добавляет класс
  тонких ошибок. Оставлен как следующий шаг усиления.

## Последствия

Ошибка разработчика (забытый `companyId`) приводит к исключению, а не к утечке.
Переход на RLS позже не потребует изменения доменного слоя.

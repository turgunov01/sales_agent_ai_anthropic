# 05. Архитектура AI-агента

## 5.1. Задача

AI играет роль продавца-консультанта конкретного магазина. Он обязан:

- отвечать на русском и узбекском, определяя язык автоматически;
- опираться **только** на данные компании (каталог + база знаний + FAQ);
- задавать уточняющие вопросы вместо угадывания;
- распознавать намерение купить и квалифицировать лид;
- получить имя и телефон;
- рекомендовать товары из каталога;
- создавать и обновлять лид;
- передавать разговор человеку.

## 5.2. Компоненты

```
AiAgentService.reply(ctx, userMessage)
   │
   ├─ LanguageDetector       → RU | UZ (детерминированно, по алфавиту и маркерам)
   ├─ PromptBuilder          → system prompt из данных компании
   ├─ ConversationHistory    → последние N сообщений в формате Claude
   ├─ ClaudeClient           → messages.create с tools
   ├─ ToolExecutor           → исполняет tool_use, подставляя companyId
   └─ AgentResult            → { text, effects[], usage }
```

`AgentResult.effects` — побочные эффекты, которые исполняет канал:
`SHOW_PRODUCTS`, `REQUEST_CONTACT`, `NOTIFY_MANAGERS`, `LEAD_CREATED`,
`LEAD_UPDATED`. Домен не знает про Telegram-кнопки.

## 5.3. System prompt

Собирается из блоков, каждый блок опускается, если данных нет:

1. **Роль** — «Ты {assistantName}, продавец-консультант магазина {company}».
2. **Язык** — правило: отвечай на языке последнего сообщения клиента
   (RU или UZ), при смешении — на языке большинства.
3. **Жёсткие правила** (анти-галлюцинации):
   - Никогда не называй товар, цену, срок или условие, которых нет в
     результатах инструментов.
   - Если данных нет — скажи прямо и предложи связать с менеджером.
   - Цены бери строго из `search_products` / `get_product`.
   - Не обещай скидку, бронь, доставку в срок, если этого нет в базе знаний.
   - Не выдумывай наличие; используй `stockStatus`.
4. **Профиль компании** — название, телефон, адрес, график.
5. **База знаний** — о компании, доставка, оплата, гарантия.
6. **FAQ** — вопрос/ответ списком.
7. **Инструкции владельца** (`AiSettings.systemInstructions`) — свободный текст.
8. **Тон** — из настроек.
9. **Сценарий продажи** — уточнить потребность → показать 2-3 варианта →
   зафиксировать интерес → взять контакт → создать/обновить лид.
10. **Состояние лида** — что уже известно (имя, телефон, бюджет, интерес),
    чтобы агент не переспрашивал.

Полный шаблон — в `apps/api/src/modules/ai/prompt.builder.ts`.

## 5.4. Инструменты (tools)

| Инструмент | Вход | Выход | Назначение |
|---|---|---|---|
| `search_products` | `query?`, `category?`, `minPrice?`, `maxPrice?`, `attributes?`, `limit?` | до 8 товаров | Подбор по запросу клиента |
| `get_product` | `productId` | карточка товара | Детали по конкретной позиции |
| `get_company_info` | `topic` (`about`\|`address`\|`working_hours`\|`delivery`\|`payment`\|`warranty`\|`faq`\|`all`) | текст | Ответы про магазин |
| `create_lead` | `interest`, `name?`, `phone?`, `budgetMin?`, `budgetMax?`, `productIds?`, `summary` | `leadId`, `status` | Фиксация лида |
| `update_lead` | `leadId`, любые поля лида | обновлённый лид | Дополнение по мере диалога |
| `request_contact` | `reason` | `requested: true` | Просьба к каналу показать кнопку «Отправить номер» |
| `transfer_to_manager` | `reason`, `urgency` | `transferred: true` | Передача человеку |

Инварианты исполнения:

- `companyId`, `customerId`, `conversationId` **никогда** не приходят от модели —
  подставляются исполнителем из контекста запроса.
- Аргументы валидируются Zod; ошибка валидации возвращается модели как
  `{"error": "..."}`, а не роняет диалог.
- `search_products` возвращает только `active = true` товары этой компании.
- Пустой результат поиска возвращается явно: `{"products": [], "message": "..."}`,
  чтобы модель не «дофантазировала».
- Максимум `AI_MAX_TOOL_ITERATIONS` итераций tool-use за один ответ.

## 5.5. Цикл выполнения

```
messages = [history..., {role: user, content: "Мне нужен диван до 8 млн"}]
loop (max 5):
    response = claude.messages.create({system, messages, tools})
    if response.stop_reason != "tool_use": break
    for each tool_use block:
        result = ToolExecutor.execute(name, input, ctx)
        collect tool_result blocks
    messages.push(assistant: response.content)
    messages.push(user: tool_results)
return text из последнего ответа + накопленные effects
```

## 5.6. Квалификация лида

`qualificationScore` (0..100) считается детерминированно, не моделью:

| Признак | Баллов |
|---|---|
| Указан телефон | 40 |
| Указано имя | 10 |
| Сформулирован интерес | 20 |
| Указан бюджет | 15 |
| Привязаны товары | 15 |

`QUALIFIED` выставляется автоматически при наличии телефона **и** интереса
(score ≥ 60). Это делает «квалифицированный лид» проверяемым фактом, а не
мнением модели.

## 5.7. Отказоустойчивость

| Сбой | Поведение |
|---|---|
| Нет `ANTHROPIC_API_KEY` | Агент выключен, клиенту — сообщение о том, что менеджер ответит; создаётся `HANDOFF_REQUESTED` |
| Таймаут/5xx Claude | Одна повторная попытка, затем вежливое сообщение + передача менеджеру |
| Превышен лимит итераций | Возвращается последний текст; в лог — предупреждение |
| Ошибка инструмента | Модель получает `{"error": "..."}` и продолжает диалог |
| `AiSettings.enabled = false` | Сообщения сохраняются, ответ не генерируется |

## 5.8. Определение языка

Детерминированная эвристика (без вызова модели):

1. Доля кириллицы/латиницы в тексте.
2. Словарь узбекских маркеров (`kerak`, `narxi`, `qancha`, `bormi`, `salom`, …)
   и русских (`нужен`, `сколько`, `цена`, `есть ли`, …).
3. Латиница + узбекские маркеры → `UZ`; кириллица без узбекских маркеров → `RU`.
4. Неопределённость → язык клиента из профиля, иначе `Company.defaultLanguage`.

Определённый язык сохраняется в `Customer.language` и `Conversation.language`.

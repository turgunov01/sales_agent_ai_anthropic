# 06. Telegram: подключение и обработка

## 6.1. Подключение бота владельцем магазина

1. Магазин создаёт бота у `@BotFather` и получает токен.
2. В админке: **Настройки → Каналы → Подключить Telegram**, вставляет токен.
3. API `POST /channels/telegram`:
   - вызывает `getMe` — проверяет, что токен рабочий, получает `username`, `id`;
   - генерирует `webhookSecret` (32 байта, hex);
   - шифрует токен (AES-256-GCM) и сохраняет `Channel`;
   - вызывает `setWebhook` с URL `PUBLIC_WEBHOOK_URL/api/v1/webhooks/telegram/{channelId}`
     и `secret_token = webhookSecret`, `allowed_updates = ["message"]`,
     `drop_pending_updates = true`.
4. Ответ содержит `botUsername` и маскированный токен.

Один канал на компанию на тип (`@@unique([companyId, type])`). Повторное
подключение перезаписывает токен и переустанавливает webhook.

## 6.2. Приём апдейта

```
POST /api/v1/webhooks/telegram/:channelId
X-Telegram-Bot-Api-Secret-Token: <webhookSecret>
```

Порядок:

1. Rate limit по IP (защита от флуда на публичный маршрут).
2. Загрузка канала по `channelId`; если нет или неактивен — `200 OK`, выход.
3. Сравнение секрета **constant-time**; несовпадение → `200 OK`, лог `warn`.
   Мы не возвращаем 401: это подсказало бы атакующему, что канал существует.
4. Немедленный `200 OK` с пустым телом.
5. Постановка задачи в in-process очередь → обработка.

## 6.3. Обработка сообщения

```
update.message
   ├─ text        → как есть
   ├─ photo       → "[клиент отправил фото]" + file_id в attachments
   ├─ voice       → "[голосовое сообщение]" + подсказка агенту попросить текст
   ├─ contact     → сохраняем phone в Customer и в активный Lead
   └─ прочее      → игнорируем
```

Шаги:

1. `upsertCustomer(companyId, telegramUserId)` — имя, username, язык.
2. `getOrCreateActiveConversation` — новый диалог, если предыдущий закрыт или
   молчал дольше `CONVERSATION_IDLE_HOURS`.
3. Сохранение входящего `Message` (`role = CUSTOMER`).
4. Если `Conversation.status = HUMAN_HANDLING` — AI не вызывается, диалог
   просто ждёт менеджера в админке.
5. Иначе — `AiAgentService.reply()`.
6. Сохранение ответа (`role = ASSISTANT`) и отправка в Telegram.
7. Исполнение эффектов:
   - `SHOW_PRODUCTS` → карточки товаров (фото + название + цена);
   - `REQUEST_CONTACT` → клавиатура с кнопкой `request_contact`;
   - `NOTIFY_MANAGERS` → системное сообщение в диалог + статус `HANDOFF_REQUESTED`;
   - `LEAD_CREATED` / `LEAD_UPDATED` → только запись в БД.

## 6.4. Ответ менеджера

`POST /conversations/:id/messages` из админки:

1. Сохраняет `Message` с `role = MANAGER`.
2. Отправляет текст в Telegram через `Channel` этого диалога.
3. Первый ответ менеджера переводит диалог в `HUMAN_HANDLING` (AI молчит,
   пока не нажмут «Вернуть AI»).

## 6.5. Формат карточки товара

```
🛋 Диван «Милан»
7 500 000 сум
Угловой, рогожка, серый, 280 см, 4 места
В наличии
```

Максимум 3 карточки за раз: больше — визуальный шум в мессенджере.
Изображения отправляются через `sendPhoto` с подписью; при отсутствии
изображения — `sendMessage`.

## 6.6. Ограничения Telegram, которые учтены

| Ограничение | Как учтено |
|---|---|
| Webhook ждёт ответ ≤ 60 с, иначе ретрай | Отвечаем `200 OK` до обработки |
| Дубликаты апдейтов при ретраях | Идемпотентность по `update_id` в памяти процесса |
| Лимит ~30 сообщений/сек на бота | Последовательная отправка, не более 3 карточек |
| Длина сообщения 4096 символов | Обрезка ответа агента с многоточием |
| Markdown ломается на спецсимволах | `parse_mode` не используем вовсе: карточки уходят обычным текстом |
